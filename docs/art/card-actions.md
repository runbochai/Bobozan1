# Card-playing sprite assets

The 37 sheets in `public/characters/actions/` reuse the project's existing character animation artwork: 13 selectable avatars, the robot, the training dummy, and 22 expedition enemies. Each transparent 1536 × 1024 atlas contains eight 192 × 256 direction cells per row, ordered S, SW, W, NW, N, NE, E, SE. The four rows are prepare, raise, release, and recover.

Only the small dragon's NW/N/NE columns (columns 4–6) were repaired for this change. All twelve repaired cells retain both wings and use the same hand throughout the gesture. The existing idle atlas is unchanged. The other five action columns are retained from the existing artwork.

Generation used the built-in `image_gen` tool in edit/reference mode with `transparent_background: true`; no CLI/API fallback was used. The effective reference images were crops of the existing idle NW/N/NE directions. The accepted original output is retained in the project workspace at `../bdrag-wings-repair/back-columns-v3.png`; its original tool output was `$CODEX_HOME/generated_images/01a0eef9-6a1e-7ab0-b24d-324d876d9240/exec-4908d3eb-e9b1-4ac9-989c-0c47b4c7ea9f.png`. Rejected attempts were not added to this repository.

The final runtime asset is `public/characters/actions/bdrag.webp`. Packing only crops complete generated cells, uses nearest-neighbor sizing, and aligns their feet to the original idle model; it does not paint, duplicate, or procedurally invent character parts. The repaired atlas is stored losslessly. Release and raised-hand coordinates are recorded in `src/data/battleActions.ts` and `src/data/battleRaisedHands.ts`.

The raised palm and elbow positions were reviewed against all 37 sheets in each of the eight directions. Each character now has explicit raised-frame coordinates; raised-hand side is not inferred from the release frame. The 35 reused characters contributed 560 measured palm/elbow points, all verified against opaque pixels in their own cells. The six notably displaced release points (three front-facing cross-body poses and three lowered back-facing hands) are also corrected in the release mapping.

The local hand/forearm perspective enlargement is enabled only for the viewer's own character after a committed move enters showdown. Browsing categories or card details does not start the animation or transform the hand UI. Opponents retain the ordinary four drawn action poses.

## Effective repair prompt

```text
Create a repaired pixel-art action sprite patch for the SAME small orange dragon in these reference images. The first reference shows the correct BACK-LEFT view (NW). The second shows correct BACK (N) and BACK-RIGHT (NE) views. Match these directions exactly: we see the back of the round head, BOTH shoulder blades and TWO small orange-gold bat wings. Do not turn the side views into full profile; the dragon's chest and eyes are NOT visible. Output a TRANSPARENT sprite sheet with exactly THREE equal columns (NW, N, NE) and FOUR equal rows (prepare, raise, release, recover), twelve full-body sprites in total. Important invariant: every sprite has TWO clearly separated visible wings, projecting left and right from the upper back, just like the references. Wings remain spread at shoulder level in every frame. Arms are distinct from wings; raising or lowering a hand NEVER removes a wing. Across rows only one arm moves and all other body features stay fixed. Row1: hand holding small black card with gold border visible outside torso near waist. Row2: same hand raised outside head silhouette holding that card. Row3: SAME hand slammed forward and downward just below wing at waist, empty open palm. Row4: same arm relaxed at side, no card. Use VIEWER-LEFT hand for left-column NW and VIEWER-RIGHT hand for middle-column N and right-column NE; never swap hands between rows. Keep horns, orange scales, gold spines, curved tail, body proportions, face direction and thick dark pixel outlines exactly consistent with the references. Feet on same baseline per row. Full bodies fit in each cell with transparent padding; no overlap. Precise grid with 3 columns x 4 rows, entire sheet 1024x1536. Crisp pixel-art edges, not smooth/vector art. Absolutely NO background texture/color, NO floor, NO checkerboard, NO text. Real transparent alpha. The purpose is to replace missing-wing animation columns; all 12 sprites MUST have BOTH wings, including the raised and released poses.
```
